# 程式碼產生指引

## 指令語法規範

- 呼叫終端機指令必須使用 `PowerShell` 語法

## 程式碼風格與語法規則

### ESLint 規則

- 使用單引號而非雙引號
- 使用分號結束陳述句
- 保持一致的縮排 (4個空格)
- 避免未使用的變數
- 使用駝峰式命名法 (camelCase)
- 換行結尾不應有多餘空白字元

### TypeScript 規範

- 為所有變數、參數和回傳值提供明確型別宣告
- 避免使用 any 型別，優先使用泛型或明確型別
- 適當使用介面 (interface) 和型別 (type)
- 遵循嚴格的空值檢查
- 優先使用箭頭函式（Arrow Function）取代傳統函式宣告

## Vue 框架規範

### 響應式狀態管理

- 只使用 Composition API，不使用 Options API
- Composition API 相關狀態，邏輯、Hooks 應該放在同一區塊
- 透過 composable 函式實現狀態邏輯重用
- 使用 ref、reactive、computed 等 Vue 3 響應式 API
- 將相關邏輯封裝在專用 composable 檔案中

### SFC 結構順序

- script 區塊必須位於最上方
- template 區塊置於 script 區塊之後
- style 區塊置於最下方

### Vue 程式碼標準

- 使用 Composition API 取代 Options API 以獲得更好的型別推斷和程式碼重用
- 實作 <script setup> 以獲得更簡潔的元件定義
- 使用 Suspense 和非同步元件處理程式碼分割時的載入狀態
- 運用 defineProps 和 defineEmits 巨集實現型別安全的 props 和事件
- 使用新的 defineOptions 來設定額外的元件選項
- 實作 provide/inject 進行相依性注入，避免深層元件的 prop 傳遞
- 使用 Teleport 元件實現類 portal 功能，在 DOM 中的其他位置渲染 UI
- 優先使用 ref 而非 reactive 來處理原始值，避免非預期的解包
- 使用 v-memo 優化需要大量渲染的列表效能
- 對不需要深層響應式的大型物件實作淺層 ref

### Vue Router 規範

- 使用路由守衛 (beforeEach, beforeEnter) 進行認證和授權檢查
- 實作路由元件的動態引入以改善效能
- 使用具名路由取代硬編碼路徑以提升可維護性
- 運用路由 meta 欄位儲存權限或版面配置等額外資訊
- 實作捲動行為選項控制路由導航間的捲動
- 使用導航重複處理防止重複導航到當前路由
- 實作 composition API 的 useRouter 和 useRoute hooks
- 使用巢狀路由實現具有父子關係的複雜 UI
- 運用 sensitive: true 設定來保護敏感的路由參數
- 實作動態路由匹配，支援路徑參數和正規表達式模式

## 樣式規範

- 使用 SASS 作為樣式預處理器
- 使用巢狀結構撰寫樣式
- 避免過度巢狀，最多不超過三層
- 使用變數儲存顏色、字型大小等常用樣式
- CSS 類別使用 kebab-case (例：`nav-list-active`, `search-card`)
- 語意化命名，避免樣式相關命名
- 優先使用元件作用域樣式 (scoped)

## 檔案與路徑規範

### 路徑和匯入規則

- 使用絕對路徑進行匯入，而非相對路徑
- 所有匯入路徑應從專案根目錄開始，使用 '@/' 前綴
- 先匯入第三方函式庫，再匯入專案內部模組
- 相關模組的匯入應分組並以空行分隔

### 命名規範

- 變數與函式: camelCase
- 類別與介面: PascalCase
- 常數: UPPER_SNAKE_CASE
- CSS 類別: kebab-case
- Vue 元件檔案: PascalCase (如 UserProfile.vue)
- TypeScript 服務/工具檔案: camelCase (如 userAuth.ts)
- 模型檔案: PascalCase (與類別名稱一致，如 User.ts)

## 圖示使用指引

- 預設使用 MDI (Material Design Icons) 圖示字型
- 在 Vue 元件中使用一致的圖示引用格式 `<Icon name="mdi-account"/>`
- 動態切換圖示時，使用計算屬性
- 建立共用圖示元件確保一致性
- 圖示尺寸使用預定義變數，避免硬編碼數值
- 確保圖示與元素垂直居中對齊
- 為需要旋轉或動畫的圖示建立專用 CSS 類別

## 文件規範

### JSDoc 註解規則

- 為所有函式、類別和方法提供一致的 JSDoc 註解
- 使用 @param、@returns 和 @throws 標籤完整描述函式行為
- 為複雜 API 實作包含實際使用情境的 @example 標籤
- 在不使用 TypeScript 時，使用 @typedef 記錄複雜物件結構
- 將文件生成設定為建構程序的一部分，確保文件保持最新
- 實作自定義模板以符合專案風格指南
