# 提交訊息指引

一律使用 `zh-TW` 來撰寫紀錄，保持訊息簡潔一致，並嚴格遵循以下格式來撰寫提交訊息：

## 提交訊息格式

```
<type>([scope])?: <short description>
[body]?
[footer]?
```

## 結構說明

1. type (必填)
    - 描述提交的類型，選擇以下類別之一：

        - `feat`: 新功能 (MINOR)
        - `fix`: 錯誤修正 (PATCH)
        - `build`: 影響建置系統或外部相依性的修改
        - `ci`: CI 設定或腳本調整
        - `docs`: 文件變更
        - `style`: 程式碼風格調整 (不影響功能)
        - `refactor`: 程式碼重構 (無功能變更)
        - `perf`: 性能優化
        - `test`: 測試新增或修改
        - `chore`: 其他雜項變更
        - `revert`: 還原先前的提交

   - 在 type 後加上 `!` 來標示重大變更，例如：`feat!: 重大功能變更`

2. scope (選填)

    - 描述影響的範圍，例如：`auth`、`dashboard`。
    - 若涉及多個範圍，可使用更廣泛的描述，例如：`project` 或 `core`。

3. description (必填)

    - 簡要說明變更內容，限 100 字元內。
    - 若涉及多檔案與多需求，應概括描述主要變更目標，例如：「重構核心模組以提升效能與可維護性」。

4. body (選填)

    - 詳細說明變更的動機與行為差異，適用於複雜變更。
    - 若涉及多檔案，應列出主要變更點，例如：

    ```
    - 調整 `auth` 模組以支援多種驗證方式
    - 優化 `dashboard` 的資料載入效能
    - 修正 `api` 超時問題
    ```

5. footer (選填)

    - 包含 Issue 關聯資訊，如：`Closes #<issue_number>`
    - 重大變更加註 `BREAKING CHANGE:` 並說明影響，適用於 MAJOR 更新

## 範例

- 一般提交：

    ```
    feat(auth): 新增 OAuth 登入支援
    ```

- 還原提交：

    ```
    revert: feat(auth): 新增 OAuth 登入支援

    This reverts commit <commit_hash>.
    ```

- 重大變更：

    ```
    fix!(api): 修正超時問題

    BREAKING CHANGE: 更新了 API 回應格式。
    ```

- 關聯 Issue：

    ```
    docs: 更新 README

    Closes #1
    ```

- 多需求統整提交：

    ```
    refactor(project): 重構多模組以提升效能與一致性

    - 調整 `auth` 模組以支援多種驗證方式
    - 優化 `dashboard` 的資料載入效能
    - 修正 `api` 超時問題
    - 更新 SCSS 樣式以統一主題與命名規範

    BREAKING CHANGE: 更新了部分 API 的回應格式，可能影響現有功能
    Closes #123, #456
    ```
