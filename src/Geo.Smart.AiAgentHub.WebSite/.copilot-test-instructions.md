# 測試開發指引

使用 Vitest 進行 JavaScript, TypeScript 和 Vue 元件的測試開發。

## 檔案結構與命名規範

### 基本檔案結構

```
src/
├── __tests__/                 # 測試根目錄
│   ├── unit/                 # 單元測試
│   ├── integration/         # 整合測試
│   ├── __mocks__/          # 模擬資料
│   └── helpers/            # 測試輔助函式
```

### 命名規範

- 測試檔案：`*.test.ts` , `*.spec.ts` ,` *.test.js` , `*.spec.js`
- 模擬資料：`__mocks__/*.ts`, `__mocks__/*.js`
- 輔助函式：`helpers/*.ts` , `helpers/*.js`

## 測試程式碼規範

### 基本測試結構

```typescript
import { describe, it, expect } from 'vitest';

describe('元件/函式名稱', () => {
    it('應該完成特定功能', () => {
        // Arrange - 準備測試資料
        // Act - 執行測試
        // Assert - 驗證結果
    });
});
```

### 程式碼風格

- 使用單引號而非雙引號
- 使用分號結束陳述句
- 保持一致的縮排 (4個空格)
- 避免未使用的變數
- 使用駝峰式命名法 (camelCase)
- 換行結尾不應有多餘空白字元
- 如果專案使用 TypeScript，則所有變數、參數和回傳值都應提供明確型別宣告

## 測試撰寫準則

### 測試案例設計

- 遵循 3A 模式：Arrange-Act-Assert
- 每個測試只驗證一個概念
- 包含正面和負面測試案例
- 測試邊界條件

### 非同步測試

```typescript
it('非同步操作測試', async () => {
    const result = await asyncFunction();
    expect(result).toBe(expected);
});
```

### 模擬物件使用

```typescript
import { vi } from 'vitest';

```typescript
import { vi } from 'vitest';

vi.mock('./dependency', () => ({
    someFunction: vi.fn().mockReturnValue('mocked'),
}));
```

## Vue 元件測試特別規範

### 元件測試結構

```typescript
import { mount } from '@vue/test-utils';
import MyComponent from './MyComponent.vue';

describe('MyComponent', () => {
    it('應該正確渲染', () => {
        const wrapper = mount(MyComponent);
        expect(wrapper.html()).toMatchSnapshot();
    });
});
```

### Composition API 測試

```typescript
import { ref } from 'vue';
import { useMyComposable } from './composable';

describe('useMyComposable', () => {
    it('應該正確運作', () => {
        const { result } = useMyComposable();
        expect(result.value).toBeDefined();
    });
});
```

## 效能與維護性考量

### 效能最佳實踐

- 使用 `beforeEach/afterEach` 重置測試狀態
- 善用 `vi.mock()` 避免實際 API 呼叫
- 適當使用 `test.skip()` 和 `test.only()`
- 考慮使用 `test.concurrent` 進行平行測試

## 文件與註解規範

### JSDoc 註解

```typescript
/**
 * @description 函式描述
 * @param {string} param - 參數描述
 * @returns {Promise<boolean>} 回傳值描述
 * @throws {Error} 錯誤描述
 */
```

### 測試描述規範

- 使用明確且具描述性的測試名稱
- 描述預期行為而非實作細節
- 使用一致的命名慣例
- 包含測試情境說明

## 持續整合考量

### 測試指令

```bash
# 執行所有測試
yarn test "vitest --environment jsdom"

# 執行特定測試
yarn test:unit "vitest path/to/test --environment jsdom"

# 產生覆蓋率報告
yarn test:coverage "vitest run --coverage --environment jsdom"
```
